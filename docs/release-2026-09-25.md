# Cleania — visual refinement and Vercel presentation release

## Scope and deployment boundary

The owner explicitly requested Vercel publication. The existing app runs on Sites/Cloudflare with D1, R2 and a trusted authentication gateway. Those bindings and the gateway are not available inside a Vercel Node.js function. A direct Next.js build initially failed on `cloudflare:workers`, confirming the runtime mismatch.

This release preserves that original architecture and adds a separate Next.js build for Vercel. **The Vercel deployment is a clearly marked demonstration, not a live booking/CRM migration.** It does not collect names, phone numbers, addresses or photos. Its final calculator screen shows the estimate without claiming that an order exists. A dedicated database, object storage and verified standalone authentication still need to be configured before accepting customers there. Permission to provision a free database was requested; no new database or paid service has been provisioned in this release.

The original Sites production deployment and its access policy are unchanged. No production records were copied or overwritten. Unrelated Vercel projects/databases were not used. Private employee source portraits, environment files, local SQLite state and rejected images are excluded from publication.

## Implemented improvements

- One shared price calculation in the hero and the full calculator; existing rates remain unchanged.
- Interruptible panel-height transitions with one live form, visible validation focus, debounced accessible price announcements and an optional reduced-motion setting.
- Stable mobile sticky action bar: no layout-height jump when it enters the viewport.
- Native smooth navigation, one-time section reveals, animated FAQ and mobile menu, with keyboard and reduced-motion support.
- Enlarged eight-sector cleaning star: finite spray, brush, cloth and shine sequence; no perpetual loop.
- Removed decorative arrows from public and CRM actions.
- Three process illustration cards and three interactive before/after examples: kitchen, office and bathroom. Clear AI labels; no invented completed customer jobs or invented case economics.
- Manual retouch of the approved hero image: only the defective PVC strip and right handle were changed; two handles use identical vertical coordinates. Rejected intermediate renders were moved into ignored `outputs/rejected-hero`, not destroyed.
- Incorrect service titles such as “Офис уборка” and “После ремонта уборка” corrected.
- Before/after image readiness is tied to the selected example, so a late old load does not unlock a different example.
- Sharing preview uses the site's own hero asset. Vercel canonical origin comes from the platform's production-domain variable. The demo is `noindex` and disallows crawling.

## Security boundary on Vercel

- `proxy.ts` allows only `GET /api/pricing` in presentation mode; all other API methods/paths return a non-cacheable 503 without processing the request body.
- The public pricing response is explicitly labelled `mode: preview` and contains the configured reference tariffs.
- Vercel never trusts client-supplied `oai-authenticated-*` headers. Those headers remain valid only behind the existing Sites gateway.
- `/crm` displays a setup explanation; no customer or employee database access occurs.
- The Vercel runtime adapter intentionally has no fake in-memory or temporary-file database. Missing infrastructure must not result in false success.

- `node --test tests/*.test.mjs`: 17/17 passed, covering quote arithmetic, focus/scroll behavior, reduced motion and the preview API allowlist.
- ESLint and TypeScript completed successfully.
- `npm run build:vercel`: optimized Next.js production build succeeded, including 17 generated static pages and dynamic endpoints.
- `npm run build`: the original vinext/Cloudflare build also completed. It reports the expected warning that its runtime ignores the Vercel-only webpack configuration.
- The compiled app was started with `CLEANIA_RUNTIME=vercel npx next start --hostname 127.0.0.1 --port 3001` for actual runtime testing, not just development HMR.
- HTTP: homepage 200; pricing 200 with preview mode and four tariff rules; GET orders 503 with the explicit no-data-saved response; robots disallows all crawling.
- Browser: document width exactly matched viewport width at 1440, 375 and 320 CSS pixels. Desktop navigation elements were within the viewport. Mobile screenshots of the comparison and final estimate were visually inspected.
- Before/after: office tab loads both images; “Показать после” gives slider value 0; keyboard End gives 100; linked CTA switches the calculator to office and 5990 ₽ for 50 m².
- Final calculator step: heading receives focus; no phone/name/file fields exist in the Vercel DOM; the send action is disabled and clearly labelled as a demo.
- Cleaning-star click starts `data-playing=true` in the compiled build. No arrow-bearing links/buttons were found on the homepage. Browser error/warning log was empty in the production-build session.

Earlier local development checks also covered 768 px, maximum calculation 107550 ₽, rapid step changes, FAQ interruption, mobile-menu closing and manual reduced-motion persistence. They are not claims of physical-device testing or benchmarked frame rates. No new order submission or notification delivery was tested in this release; a prior attempted order test was not approved because it could trigger external notifications.

## Reproduction

```sh
npm ci
node --test tests/*.test.mjs
npm run lint
npx tsc --noEmit
npm run build:vercel
CLEANIA_RUNTIME=vercel npx next start --port 3001
```

For the existing Cloudflare development/runtime, retain `npm run dev` and `npm run build`. Do not set Vercel presentation variables for a live Sites deployment.
